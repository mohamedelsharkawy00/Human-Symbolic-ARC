COMPOSER (the original goal behind the op-palette drawer)
  The drawer is currently a read-only browser: drag it open, tab through op
  families, read the ops. Next layer is making it a real composer:
  - Click an op to append it into a draft program.
  - Live result of the draft via the existing hover-preview engine
    (gui.hpp ~700-1016: execute_tree_via_flat per example, shows accumulator
    + object strip).
  - Annotation pickers (choose the [c]/[k] variant when appending an
    annotated op).
  - Reorder / delete ops in the draft.
  - Tooltips per op (needs op-description metadata — see below).
  Hooks already in place to build on: classify_op() groups ops into the 7
  tabs; the drawer already owns click_zones for tabs, so op boxes just need
  their own zones + a draft-program buffer in global_app_state.

GROUP PUZZLES BY SIZE RULE (GUI, later)
  Browse/sort/filter the puzzle list by the inferred dimension_rule
  (Identity / Scale / Fixed / BoundingBox). infer() already computes it per
  puzzle at load. Uses: jump to all Scale puzzles when testing a tiling op;
  see which class the unsolved tasks cluster in; pick benchmark subsets per
  class. Could extend to other inference facts later (bg color, kept
  fraction, output-colors count).

OP DESCRIPTIONS METADATA
  Per-op one-line descriptions for tooltips in the composer. Either a new
  X-macro field in NODE_PRIMITIVES (environment.hpp) or a sidecar table +
  generator. Presentation-only, so a gui.hpp-local lookup (like classify_op)
  is also fine.
