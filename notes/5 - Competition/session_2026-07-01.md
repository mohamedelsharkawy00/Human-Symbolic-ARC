## 1. Op-palette drawer

A top-edge overlay that lets you browse every DSL op by family while the live
puzzle/result stays visible. Toggled entirely by **dragging** — no key, no click.

### Behaviour
- **Top-edge drawer.** A fixed-height panel that conceptually lives *above* the
  screen and slides down; its top rows scroll in last (like a real window shade).
- **Drag-only open/close.** Grab the handle **or any empty space in the panel
  body** and drag. The bottom edge moves *with* the cursor (grab offset
  preserved — no teleport/jump). On release it **snaps**: past halfway → fully
  open, else → closed. No click-toggle, no `O` key (both removed).
- **Resizable past the header band** — can be pulled down far enough to cover
  every header row including INPUT/OUTPUT (panel_h clamped to >= grid_data_start_y).
- **Handle:** a wide, short, 4-rect stepped-trapezoid wedge (wide top, narrow
  base ≈45°), no outline. Dim grey (11) idle → bright grey (5) when the cursor is
  directly over it (cheap "fade", no alpha/shader work — the pipeline has no alpha).

### Layout
- **7 tabs, in pipeline-authoring order:**
  GET → REDUCE → SELECT → TRANSLATE → MAP → GENERATE → COMBINE.
  Order validated against a real solution (05a7bcf2): every line runs
  GET…→COMBINE left-to-right. Seam = "what the op does to the layer"; the
  classifier `classify_op()` in gui.hpp assigns all 65 ops to exactly one tab.
- **Alphabetical** ops within each tab.
- **Centered** tab row and centered op rows (rows grouped first, then centered).
- **Quad-thickness** white border (top/bottom/side; top hidden while off-screen).
- **Thinnest grey separator** hugging the bottom of the tab row.
- **Equal vertical gaps**: top-border → tabs → separator → ops (all = `vgap`).
- **Tripled horizontal edge padding** (`hmargin = base_margin * 3`).

### Click-swallow (earlier fix, still in place)
When open, the drawer overlays the header band. `drawer_blocks_zone()` stops
clicks in the drawer region from falling through to the buttons underneath
(this was the EXIT-button crash). Only tab zones are live there.

## 2. Deep-search scoring fix

- **Symptom reported:** search seemed to "stop at 14-15 nodes".
- **Diagnosis:** depth histogram from the log proved the search DOES reach 24
  nodes. The real bug was `GPU_KERNEL_POOL_SIZE = 24` in cuda_dsl.cuh — deep
  programs (~2 pool slots/op) hit the clamp in `gpu_acquire` (cuda_solver.cu:76)
  and silently overwrote slot N-1 → corrupted scores for deep candidates, so
  genuine deep solutions were mis-scored and pruned.
- **Fix:** `GPU_KERNEL_POOL_SIZE` 24 → 48 (= 2 × MAX_SEARCH_DEPTH). Added
  `static_assert(GPU_KERNEL_POOL_SIZE >= 2 * MAX_SEARCH_DEPTH)` in
  dsl_executor.hpp so raising the depth again fails the build loudly.
- **Cost:** per-job context ~0.7MB → ~1.4MB (still under the old 2.8MB).
- Scanned other depth-era assumptions (int8_t node/op counts, spine[] and
  bucket_cutoff[] arrays) — all either scale off MAX_SEARCH_DEPTH or have
  int8/GPU_MAX_OPS headroom. No other latent caps.

## Gotchas hit (so we don't re-learn them)
- `near` is a legacy Windows macro — can't use it as a variable name.
